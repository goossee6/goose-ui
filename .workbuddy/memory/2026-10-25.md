## 第三轮：DatePicker / TimePicker / DateRangePicker 空状态高度跳变

现象：demo 里同一行 `<DatePicker bind:value>` / `<DatePicker value="" placeholder="空状态">` / 禁用的
`<DatePicker value="...">` 三个高度不一致，空状态那个更高（用户截图）。

根因：三个触发器都是 `<button class="dp-trigger">` + 两个 `<span>`，高度由 padding 撑出
（`padding: var(--sp-md)`），内容行盒高度取决于字体度量：值分支是等宽数字（`--font-mono`），
空状态分支是 CJK 占位文案，命中不同的回退字体 → 行盒高度不同 → 整个控件高矮不一。实测本机
headless 下三态都是 33px（比 Input 的 `--height-md: 36px` 还矮 3px），用户环境里空状态被撑到 44px。

修法（3 个文件同一套）：
- 触发器改定高 `height: var(--height-md)` + `line-height: 1.2`（显式数值，行盒不再受字体度量影响），
  左右 padding 保留、上下 padding 去掉 → 三态恒为 36px，与 Input/Button 的 `--height-md` 对齐。
- `.dp-value/.dp-placeholder`（tp-/drp- 同）补 `min-width: 0` + `nowrap` + `overflow: hidden` +
  `text-overflow: ellipsis`：定高后长文案改成截断而不是换行撑高。
- 每处都写了注释说明「CJK 占位文案回退字体行高不同」这个坑。

验证：构建 demo 后用 chrome --headless 注入脚本量 `.dp-trigger` / `.drp-trigger` / `.tp-trigger`，
全部 h=36.0 lh=15.6px（改前 33.0）；截图确认三个框对齐。`pnpm check` 0 error/0 warning，
`pnpm test` 14/14。

## 第四轮：Checkbox 勾选导致整页跳动

现象：Toggle 页「实际场景：设置项」里点「我已阅读并同意用户协议」的 Checkbox，页面会跳。

根因（已用 headless 注入脚本复现）：`.checkbox-label` 没有 `position: relative`，里面视觉隐藏的
`<input type="checkbox">` 是 `position: absolute; width/height:1px`，无定位祖先 → 逃到最近的定位元素处，
实测落在 label 下方 **1555px**。点 label 时浏览器把 input 聚焦（`document.activeElement` = input），
于是把那个位置滚进视口：`.layout-content` 的 scrollTop 从 **24 → 1198**（跳 1174px）。
Radio 是同一套写法（`.radio-input` 也是 absolute），实测 input 偏离 label 143px，只是没那么远没触发滚动。

修法：
- `Checkbox.svelte`：`.checkbox-label` 加 `position: relative`；`.checkbox-input` 补 `top:0; left:0; margin:0`
  （Chrome 给 checkbox 的 UA margin 是 `3px 3px 3px 4px`，不清掉会偏离 3~4px）。
- `Radio.svelte`：`.radio` 加 `position: relative`；`.radio-input` 补 `top:0; left:0`。
- 两处都写了注释说明「隐藏 input 必须落在 label 内，否则聚焦会滚动整页」。

验证：`.checkbox-input` 相对 label dy=dx=0，点击前后各滚动容器 delta 全 0，checked 正常 true/false 切换；
radio `offsetParent` 变成 label 自身。`pnpm check` 0/0，`pnpm test` 14/14。
