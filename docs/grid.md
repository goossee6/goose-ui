# 栅格与刻度

goose-ui 的所有间距、字号、圆角都来自**一张有限的刻度表**。组件里不写裸 `px`。

## 为什么是「刻度」而不是「4 的倍数」

业界刻度并不统一：Material 是 8dp 布局网格 + 4dp 基线（但 M3 的 spacing 含 2、6，圆角含 28），
Fluent 用 4px，Carbon 用 8px 的 `mini-unit`。共同点不是「必须 4 的倍数」，而是三条性质：

1. **有限** —— 取值可枚举，不是连续量；
2. **可组合** —— 任意两档能相加/相减得到另一档，所以「上下 4、左右 8」有写法；
3. **可推导** —— 命名本身携带数值，读到 `--space-3` 就知道是 12px。

旧 token 不满足后两条：`--padding-sm: 0 8px` 是**复合值**，只能整块用；想表达「上下 4 左右 8」
没有 token 可用，只能硬编码。这正是组件里散落几百处 `px` 的根本原因——不是偷懒，是没有落点。

## 空间刻度

主网格 4pt，子刻度 2pt。单位为 `--space-{n}`，**n = px / 4**；子刻度写成 `n.5`。

| Token | 值 | 典型用途 |
| --- | --- | --- |
| `--space-0-5` | 2px | 紧凑列表的行间、图标与文字的贴身间距 |
| `--space-1` | 4px | 最小内边距、标签内边距 |
| `--space-1-5` | 6px | 小号标签、紧凑控件的横向内边距 |
| `--space-2` | 8px | 默认内边距、控件内间距 |
| `--space-2-5` | 10px | 小号控件的横向内边距 |
| `--space-3` | 12px | 卡片内边距、表单项间距 |
| `--space-3-5` | 14px | 过渡档（见下方「归位」） |
| `--space-4` | 16px | 区块内边距、段落间距 |
| `--space-5` | 20px | 大号控件内边距 |
| `--space-6` | 24px | 卡片间距、页面左右留白 |
| `--space-7` | 28px | 区块内间距 |
| `--space-8` | 32px | 区块间距 |
| `--space-10` | 40px | 大区块间距 |
| `--space-12` | 48px | 页面级分节 |
| `--space-14` | 56px | 页面级分节 |
| `--space-16` | 64px | 空状态留白 |
| `--space-20` | 80px | 空状态留白 |
| `--space-24` | 96px | 空状态留白 |

**2pt 子刻度为什么必须存在**：实测全库有 63 处 `2px`，比 `8px`（34 处）和 `4px`（15 处）都多；
`6px` 也有 24 处。它们集中在 `gap`、`padding` 这种密集处（Calendar 日期格之间、标签内边距）。
把这些值归位到 4 的倍数会让间距整体松一档，累积偏差肉眼可见。Material 自己也保留 2 和 6。

**只用于间距的属性**：`padding` / `margin` / `gap` / `row-gap` / `column-gap` / `inset` /
`top` `right` `bottom` `left`。

## 字号刻度

| Token | 值 | 用途 |
| --- | --- | --- |
| `--fs-10` | 10px | 角标、极小注记 |
| `--fs-11` | 11px | 标签（Tag sm）、时间戳 |
| `--fs-12` | 12px | 辅助文字、表头 |
| `--fs-13` | 13px | 紧凑正文（列表、菜单项） |
| `--fs-14` | 14px | 默认正文 |
| `--fs-16` | 16px | 标题、大号控件 |
| `--fs-18` | 18px | 小标题 |
| `--fs-20` | 20px | 页面标题 |

字号刻意**不进 4pt 网格**。14px 是中文正文的甜点，为了网格改成 16px 会让所有密集界面变松散；
13px 是 macOS 列表的通行值。字号各自独立成档，档与档之间差 1~2px 是正常的。

行高取 4 的倍数（16 / 20 / 24 / 28 / 32），走 `line-height` 无单位倍数或固定值。

## 圆角刻度

| Token | 值 | 用途 |
| --- | --- | --- |
| `--radius-xs` | 2px | 高亮标记、极小色块 |
| `--radius-sm` | 4px | 小控件、标签 |
| `--radius-md` | 6px | 按钮、输入框（默认） |
| `--radius-lg` | 8px | 卡片、浮层 |
| `--radius-xl` | 12px | 大面板、对话框 |
| `--radius-full` | 9999px | 胶囊、圆形头像 |

圆角保留 2px 子刻度（4 / 6 / 8 / 12）。36px 高的按钮从 6px 推到 8px 会明显变「圆」，
这是视觉敏感区，不值得为了网格牺牲。

## 尺寸不进刻度

`width` / `height` / `min-*` / `max-*` 里的大值是**组件尺寸**，不是间距，**不适用空间刻度**。

尺寸的正确形态是**档位**，不是刻度：`--height-sm/md/lg`（28 / 36 / 44）配合组件的
`size="sm|md|lg"`。刻度是连续量的离散化，档位是枚举——把按钮高度写成 `--space-7`（28px）
在语义上是错的，改刻度时会连累所有尺寸。

同理，`--checkbox-*` / `--toggle-*` / `--radio-*` 这类成组的组件尺寸继续留在 theme.css 里，
它们是一套独立的档位表。

## 不参与刻度的值

以下永远保持字面量，token 化只会增加噪音：

| 类别 | 取值 | 原因 |
| --- | --- | --- |
| 描边 | `1px` / `2px` | 描边不是间距。归位到 2/4 会让边框变粗、边缘发虚 |
| `outline` / `outline-offset` | `2px` / `-2px` | 焦点环是固定视觉规格，跟布局无关 |
| `box-shadow` | 任意 | 阴影偏移与模糊是光学参数 |
| `transform` / `translate` | 任意 | 位移量属于动画，不属于布局 |
| `letter-spacing` | 任意 | 字距按字体度量定 |
| `stroke-width` | 任意 | SVG 线条 |

## 刻度外的值：哪些归位、哪些保留

归位与保留的分界不是「不在网格上就改」，而是**这个 px 表达的是间距还是别的语义**。

### 已归位

| 现值 | → | 位置 |
| --- | --- | --- |
| `3px 8px` | `4px 8px` | CodeBlock 复制按钮内边距 |
| `5px 0 5px` | `4px 0 4px` | Page 目录项 |
| `3px` | `4px` | ToggleGroup 容器内边距 |
| `12.5px` | 13px | CodeBlock 代码字号 |
| `15px` | 16px | Header 标题字号 |
| `2px`（圆角） | `--radius-xs` | DataTable 高亮标记 |
| `--tag-pad-sm/md` `3px 6px` / `4px 9px` | `2px 6px` / `4px 8px` | Tag 档位 |
| `--togglegroup-pad-*` `2/8/16px` | `4/6/8px` | ToggleGroup 档位，与 Tabs 分段模式统一 |

### 刻意保留

这些值看起来「不在网格上」，但 token 化会掩盖真实意图：

| 值 | 位置 | 为什么不改 |
| --- | --- | --- |
| `-1px` | Page 目录 `margin-left`、PillTrack `bottom` | 压住相邻 1px 边框的光学补偿 |
| `1px` | Toggle 滑块 `left` ×4、Typewriter 光标 | 描边补偿与光标贴合，1px 是唯一正确的量 |
| `-5px` | Tooltip 四向箭头偏移 | 箭头偏移 = 箭头半宽，跟着箭头尺寸走，不是间距 |
| `72px` | Wheel 的 `top` 与 `padding` | = 2 × band 高度（36px），滚动居中的几何推导 |
| `var(--front-h, 36px)` | NotificationProvider | 这是 **var fallback**（通知卡片高度），不是间距 |
| `min(--radius-md, 10px)` | Button 图标按钮 | 圆角上限 = 半高，属几何约束 |
| `1px` 圆角 | PillTrack | 近乎直角的下划线指示条 |

### 尺寸档位为什么大多是 28/36/44 这种值

尺寸是**枚举**，不是刻度的子集。`--height-sm/md/lg` 取 28 / 36 / 44，三档等差 8、全是 4 的倍数，
正好落在 Material 3 的 density 档（-3 / -1 / +1）上。按「刻度推导尺寸」反而会破坏档位语义——
把按钮高度写成 `--space-7`（28px）之后，改一次刻度就动摇了所有组件的高度。

同类保留的还有：`--checkbox-*` 14/18/22（跟字号走的 2pt 步进）、`--radio-dot-*` 5/6/7
（必须与 radio 直径配比才同心）、`--titlebar-h` 42px（桌面标题栏的平台约定）。


## 命名规则

1. 数值刻度按「数值本身」命名：`--space-3` = 12px、`--fs-13` = 13px。**不要**用 `--space-md` 这种
   语义名——语义名无法组合，也无法推导，是旧体系的核心问题。
2. 语义别名保留，但只能**指向**刻度，不能自己存值：

   ```css
   --sp-md: var(--space-2);      /* 对 */
   --sp-md: 8px;                 /* 错，会分裂成两个事实来源 */
   ```

3. 组件的档位（`size="sm|md|lg"`）继续用语义名，它们的值是档位而非刻度。
